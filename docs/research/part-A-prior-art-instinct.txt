# Prior art for a concept-link layer over LLM chat output (Research brief A)

Date: 2026-11-10. Prepared by Instinct for Outbox. Scope: products and prior art only (part B, term extraction/defining techniques, is with the second researcher; Hermes internals deliberately not covered). Every claim carries a source URL; items marked [highlight-only] come from search-result excerpts, not a full page read; items marked [inference] are my synthesis, not a sourced fact. Repo "last activity" is GitHub's `updated_at` (last push), a close proxy for last commit.

## One-paragraph answer

Nothing in a mainstream AI chat or coding product today does what the brief describes: automatic linking of terms in an answer to hover definitions plus a fuller side-pane explanation. Every assistant (ChatGPT, Claude, Gemini, Copilot Chat, Cursor, Windsurf, Phind, Kagi) requires the user to select text and issue a prompt ("explain this") - the explanation arrives as another chat turn, not as a layered tooltip/side-pane over the answer. The two places that *do* ship the target interaction are adjacent: Semantic Scholar's Semantic Reader (click a dotted-underlined term, get an AI-generated contextual definition in place) and Perplexity's Comet browser (select text anywhere, floating assistant with a Define action). The richest prior art is outside AI chat: ScholarPhi's position-sensitive definition tooltips and "declutter" filter (the closest existing answer to your "link back to first use" requirement), Wikipedia page previews (the canonical hover-contract: ~650 ms delay, easy opt-out), Kindle Word Wise (difficulty-scaled inline hints), Obsidian page previews, and LSP/IDE hover. On your two named gaps: flagging model-coined terms has exactly two precedents I could find (ScholarPhi's nonce-word detection inside papers, and a Pony-lang "flag invented jargon" code-review skill), and linking a term to its first use in a *conversation* (as opposed to a document) appears to be genuinely unbuilt - the nearest artifacts are ScholarPhi's within-paper usage lists and a 2020 patent on in-chat context links. Details, a comparison table, and five designs worth copying below.

## Section 1 - AI chat and coding products

**Semantic Reader (Semantic Scholar / AI2)** - the closest shipped product to the target design. In an augmented PDF reader, terms and acronyms carry a dotted underline; clicking shows an AI-generated definition based on the term's context *in that paper*, without losing your place. Trigger: click (not hover). Definitions: generated per-document context. Not chat output, but the exact tooltip-over-dense-text interaction. Source: https://www.semanticscholar.org/product/semantic-reader

**ChatGPT** - no automatic term linking or hover definitions in answers. Since 2024 you can highlight part of a response and click the quote icon, which inserts the selection into your next prompt so you can ask for clarification manually. An OpenAI community feature request asking for an "Ask ChatGPT" action on selected text in the desktop app confirms the gap. Sources: https://pupuweb.com/how-to-highlight-chatgpts-response-for-follow-up/ [highlight-only], https://community.openai.com/t/feature-request-ask-chatgpt-for-selected-text-in-the-current-chat-for-desktop-app/1387522 [highlight-only]

**Claude / Claude Code** - same gap. Selecting text in an assistant response offers "Reply" and "Side chat" actions, both requiring a typed prompt; an open feature request (Oct 2026) asks for a one-click "Explain" selection action precisely because "the typing is enough friction that I often skip the question." Source: https://claudeissues.com/issue/99157-selection-action-one-click-explain-into-side-chat-plus-shortcut [highlight-only; third-party issue tracker, not an official Anthropic source - treat as indicative]

**Gemini** - no in-answer term linking. Its learning investments are Guided Learning (Socratic tutoring mode, study plans, comprehension checks) and "immersive explorations" (interactive scenes where you tap a label to dig a layer deeper) - concept exploration as a separate surface, not annotations on chat answers. Sources: https://blog.google/products-and-platforms/products/gemini/guided-learning-google-gemini/, https://blog.google/innovation-and-ai/products/gemini-app/immersive-explorations-student-hub/

**Perplexity / Comet browser** - Comet's Inline Assistant: select text on any page (or in an input field), a floating button appears with actions including **Define** ("get definitions for terms or phrases"), Summarize, Fact check, Translate, Ask anything. Trigger: selection + click, works on any web text including chat output rendered in the browser. Definitions: LLM-generated on demand. Source: https://www.perplexity.ai/help-center/comet/en/articles/13533742-inline-assistant

**Cursor** - the most relevant coding-tool precedent: "AI Previews" (beta, v0.26, Feb 2024): hold Shift while on a symbol in code to get quick AI-generated notes about it - hover-triggered, ephemeral, in-place. It operates on code symbols in the editor, not on prose in chat answers, and appears to still be experimental. Separately, Cursor chat explanations are prompt-driven (@-symbols, codebase context). Sources: https://cursor.com/changelog/0-26, https://devforgeacademy.com/tutorials/cursor/cursor-chat-and-context [highlight-only]

**GitHub Copilot Chat, Windsurf, Phind** - all explain-by-prompt, none annotate answer text. Copilot: inline chat / "generate explanation of this code block" via chat commands (Microsoft Learn module). Windsurf: code lenses above each semantic block ("Explain" opens a Cascade conversation; every Cascade message costs a credit, which Reddit users complain about - cost is a real reason users *avoid* asking for explanations) or right-click "explain selected code" in the VS Code plugin. Phind: chat with codebase context, @-mentions. Sources: https://learn.microsoft.com/en-us/training/modules/generate-documentation-using-github-copilot-tools/, https://www.youtube.com/watch?v=sr_kGYYjFaE (Windsurf University, Code Lenses), https://www.reddit.com/r/windsurf/comments/1k58dke/ [highlight-only], https://marketplace.visualstudio.com/items?itemName=phind.phind

**NotebookLM** - no in-answer term links, but two relevant moves: (1) Reports can auto-suggest a "glossary of key terms" for a scholarly source - a generated, document-scoped glossary as a first-class artifact; (2) flashcards/quizzes have an "explain" button that generates a detailed overview *with citations back to the source material* - explanation with provenance. Source: https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-student-features/

**Elicit, Consensus, Kagi Assistant** - I found no term-definition or annotation feature in any of them. Kagi's documented feature list (model choice, web access toggle, lenses, file upload, export) contains nothing like it; Elicit/Consensus are oriented to paper search, summaries, and comparison tables. Absence claim is [inference] from current feature lists, not a confirmed "they don't have it." Sources: https://help.kagi.com/kagi/ai/assistant.html, https://latrobe.libguides.com/artificial-intelligence-for-researchers/research-assistants

**Arc / Dia (The Browser Company)** - Arc Max's "5-Second Previews" (Oct 2023): hover a link (Shift+hover off whitelisted pages) and an AI-generated summary preview appears inline - the best-known *hover-triggered AI context* pattern in a mainstream product, and user reaction is instructive: TidBITS found summaries well done but "just too easy to load and scan the page myself" - hover previews must beat opening the thing. Dia: chat sidebar on any page, highlight a phrase to ask about it specifically. Sources: https://www.theverge.com/2023/10/3/23898907/arc-max-ai-browser-mac-ios, https://tidbits.com/2023/10/06/arc-web-browser-introduces-focused-ai-features/, https://www.youtube.com/watch?v=W0m-Qnb7r7Q [highlight-only]

**Readwise Reader Quick Lookup** (straddles AI/non-AI; put it here since it is LLM-powered) - select 1-3 words in the mobile reader, a bottom panel opens with three tabs: **Define** (plain dictionary-style), **Lookup** (explains the selection *in the context of what you're reading* - "handy for characters, places, or domain-specific terms that a plain dictionary won't capture"), Translate. That Define/Lookup split maps cleanly onto your tooltip vs side-pane split. Source: https://docs.readwise.io/reader/guides/ghostreader/quick-lookup

## Section 2 - Hover-definition and term-linking patterns outside AI

**Wikipedia page previews (hovercards)** - the canonical at-scale hover pattern, and the interaction details are documented: blue links are Wikipedia's most-used interactive elements (~230M pageviews/month, ~2M link hovers/min); some people *read by hovering*, so previews fire constantly unless gated - Wikipedia added a deliberate **~650 ms delay** before showing a preview and made the feature easy to disable. Lesson: delay and opt-out are not polish, they are the feature. Source: https://wikimediafoundation.org/news/2018/04/18/how-we-designed-page-previews-for-wikipedia/

**MDN Web Docs glossary** - curated glossary with strict authoring rules: first paragraph max two sentences, understandable immediately, every term in a definition links onward, ends with "See also". Lesson: the *definition content* is a separate discipline; short + self-sufficient + onward links. Source: https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Howto/Write_a_new_entry_in_the_glossary

**Kindle Word Wise** - simple definitions shown *inline above* difficult words (no interaction needed at all), with an adjustable difficulty slider controlling how many words get hints; tap a hint for more definitions/synonyms. Lesson: zero-click progressive disclosure, and density scales to the reader. Sources: https://www.amazon.com/gp/help/customer/display.html?nodeId=201645250, https://www.makeuseof.com/how-to-enable-use-word-wise-kindle/ [highlight-only]

**LingQ** - click a word, dictionary panel opens in a sidebar; words carry status colors (blue = new, yellow = learning). Community complaints when suggested meanings got hidden behind extra clicks show lookup *cost* dominates: users want the meanings visible without mousing over. Source: https://forum.lingq.com/t/first-look-at-the-new-reader-on-web/2622671 [highlight-only]

**Obsidian** - core Page Preview: Ctrl/Cmd+hover a link shows a popover of the target note; the Hover Editor community plugin turns that popover into a full editable, draggable, resizable, *pinnable* editor. Lesson: users graduate from peeking to working inside the popover; pinning bridges tooltip and side pane. Source: https://community.obsidian.md/plugins/obsidian-hover-editor

**Explorable Explanations (Bret Victor, 2011)** - the intellectual frame: active readers ask questions of text; "contextual information allows the reader to learn related material just-in-time, and cross-check the author's claims." Your layer is just-in-time contextual information for machine-authored text. Source: https://worrydream.com/ExplorableExplanations/

**IDE hover / LSP** - VS Code's HoverProvider: hover a symbol, get type info and docs in a widget; keyboard-accessible. Programmers are already trained to expect hover = definition/docs. Source: https://code.visualstudio.com/api/language-extensions/programmatic-language-features

**NN/g tooltip guidelines** - the warning list: don't put task-vital information in a tooltip (tooltips disappear); keep content brief microcontent; support keyboard as well as mouse hover. For your design this argues: tooltip = nice-to-have gloss, side pane = the real content. Source: https://www.nngroup.com/articles/tooltip-guidelines/

## Section 3 - Browser extensions, OSS projects, repos

Stars and last-activity dates checked live on GitHub, 2026-11-10.

- **allenai/scholarphi** - https://github.com/allenai/scholarphi - 428 stars, Apache-2.0, created 2019-07, last activity 2026-10-27. The ScholarPhi implementation: entity detection, definition extraction, tooltip UI, declutter filter over scientific PDFs. The most mature codebase in this list and the reference architecture for term-level augmentation.
- **mohamedsadiq/LightUp** - https://github.com/mohamedsadiq/LightUp - 37 stars, last activity 2026-10-12. Chrome extension: "AI genius annotations for every page on the web" - select text, get AI annotations in place.
- **ponylang/llm-skills** - https://github.com/ponylang/llm-skills - 5 stars, last activity 2026-11-09. Not an annotation UI - an LLM skill set whose code-review editor persona **flags invented jargon**: terms that "read like real technical vocabulary but mean something mundane the writer coined on the spot" (examples: "green-skip", "main miss"). It targets coined terms a reader can't decode, leaves real domain vocabulary alone, and checks the rest of the project before flagging when unsure. Direct prior art for your invented-terms gap. Commit: https://github.com/ponylang/llm-skills/commit/0bf3bde6b0402ef077caf5064bdaed0de98596be
- **nikhilsi/recurate** - https://github.com/nikhilsi/recurate - 4 stars, last activity 2026-10-28. Chrome + VS Code; annotates *AI chat responses* (Claude, ChatGPT, Copilot) with highlight/strikethrough/dig-deeper feedback. Not definitions, but it is prior art for per-span interaction layered over LLM output in the chat UI itself.
- **codleed/zegoop** - https://github.com/codleed/zegoop - 1 star, last activity 2026-10-12. Chrome extension with dual cursor modes; AI mode gives Explain / Simplify / Define on selected text, multi-LLM (OpenAI, Anthropic, Gemini, Grok).

The closest OSS analog to the full loop you describe: select an unknown word while reading markdown in the browser, an AI drafts a dictionary entry, you save it, and **from then on the term auto-links everywhere with a hover balloon** that leads to the dictionary page; it matches across decorations and avoids code blocks. Define-once, link-forever.
- **Explain by AI** (Chrome Web Store, closed source) - https://chromewebstore.google.com/detail/explain-by-ai/pedcfhianhacdpagbdejgldggojgfpjk - ~43 users, v1.5.0 [highlight-only]. Select text, context-aware explanation popup. Listed as market evidence that selection-popup explainers are a commodity; none do automatic term detection on chat output.

Observation [inference]: the extension ecosystem has many selection-triggered explainers and essentially nothing that *automatically* detects and annotates terms in LLM chat output - automatic detection + coined-term handling is the open space.

## Section 4 - Academic / HCI work

**ScholarPhi (Head, Lo, Wang, Chang, Bragg, Hearst, Weld - CHI 2021)** - https://dl.acm.org/doi/fullHtml/10.1145/3411764.3445648 - The foundational paper for this exact problem in documents. Key concepts: **nonce words** - terms "coined for a particular use," localized to one document, which a reader *cannot know before reading* but which are defined somewhere within it - this is the formal name for your "terms the model invented / carried from hidden reasoning." Features: position-sensitive definition tooltips (if multiple definitions exist, show the most recent one *before* the clicked use); each definition hyperlinked to the passage it was extracted from (jump-to-definition); "declutter" filter lowlights every sentence not containing the selected term (instant usage map); equation diagrams; a priming glossary prepended to the document. Measured: in a usability study, scholars answered questions about a paper in significantly less time while viewing less of it, reported it easier, were more confident, and said they would use definition tooltips frequently. Also honest about limits: contemporary definition-extraction algorithms needed improvement. (Berkeley writeup: https://www.ischool.berkeley.edu/news/2021/scholarphi-novel-interface-reading-scientific-papers)

**Paper Plain (August, Wang, Bragg, Hearst, Head, Lo - ACM TOCHI 2023)** - https://dl.acm.org/doi/full/10.1145/3589955 - Medical papers for lay readers; four NLP features: key-question index, answer gists, section gists (in-situ plain-language summaries), and click-a-term definitions. Formative study (n=12): beyond unknown terminology, readers struggled to know *which parts to read*. Main study (24 participants, partial within-subjects): lower self-reported reading difficulty, higher confidence of finding everything of interest, **no loss in comprehension accuracy**. Nuance worth stealing: definitions were appreciated but used *less* when the key-question index was available - guidance toward the right passage can beat term-level glosses; term definitions alone are not the whole answer.

**Hallucination/confabulation detection limits** - "A Geometric Taxonomy of Hallucinations in LLMs" (arXiv preprint) - https://arxiv.org/html/2602.13224v1 [preprint, not peer-reviewed]. Distinguishes unfaithfulness, confabulation (invented content), and factual error; finds embedding-based detection works for the first two but factual-error detection sits near chance (AUROC ~0.478) because "embeddings encode distributional co-occurrence, not correspondence to external reality." Implication for invented-term flagging: detecting that a term is *unusual* is tractable; verifying whether it is *real* requires external grounding (search/knowledge base), not the model's own representations.

**Adjacent HCI references** - NN/g tooltip guidelines (above) and the Semantic Reader productization of ScholarPhi (definitions-on-demand shipped to a large user base: https://www.semanticscholar.org/product/semantic-reader) are the bridge from lab results to production behavior.

## Section 5 - Gaps: what nobody does well

1. **Automatic term annotation of chat answers.** Every major assistant stops at select-and-ask. There is no shipped product that parses an assistant turn, detects terms worth defining, and links them without a user gesture. The nearest are Semantic Reader (documents, click-triggered) and GlossPop (0-star personal project). [Verified by the feature-list survey in Section 1; absence claims marked where inference.]
2. **Flagging model-coined terms.** Two precedents only: ScholarPhi's nonce-word detection (works because a paper *defines* its nonce words somewhere - chat answers often don't) and ponylang/llm-skills' invented-jargon flagger (code-review persona, checks the project before flagging). Nothing in consumer chat. The arXiv taxonomy result suggests "is this term real?" cannot be answered from the model's embeddings alone; it needs an external check (search, glossary, codebase). Distinguishing real-jargon vs coined-vs-misused is an open design problem, not a solved one.
3. **Linking a term back to first use in a conversation.** ScholarPhi's usage lists + declutter do this within a document (and its "most recent definition before use" heuristic is exactly the semantics you'd want per-turn). In chat, the only artifact I found is a 2020 Indian patent application for generating in-chat links to referenced moments (https://www.dipankar.cc/patent/chat-context-link-generation/ [highlight-only, individual inventor, status unverified]) - no shipped product, no OSS. Conversation-scoped "where was this term established?" is unbuilt.
4. **Interaction cost vs. density calibration.** Wikipedia's 650 ms delay + opt-out, Arc's "just open the page" shrug, and LingQ's hide-the-meanings backlash triangulate: the annotation layer dies if it fires too eagerly, and also if it hides answers behind gestures. Nobody has tuned this for dense LLM prose specifically.
5. **Definitions with provenance in chat.** NotebookLM's explain-with-citations and ScholarPhi's jump-to-source both attach provenance; chat explainers (Comet Define, ChatGPT quote-ask) return unattributed prose. A definition that says where it came from (this conversation, the codebase, the web) is a differentiator.

## Designs worth copying for the spike (ranked)

1. **ScholarPhi's position-sensitive definitions + declutter** - for each term, find where it was established earlier in the conversation, show that as the tooltip's source with a jump link, and offer a "show all uses" filter. Solves gap 3 with proven, studied mechanics (measured faster comprehension, higher confidence).
2. **Wikipedia's hover contract** - ~650 ms hover delay before the tooltip, trivial disable, click-through to the fuller view (your side pane). Cheap, and it is the difference between delightful and infuriating at high link density.
3. **Readwise's Define/Lookup split** - tooltip = short dictionary-style gloss; side pane = what the term means *here*, in this conversation's context. Keeps the tooltip honest microcontent per NN/g and gives the pane a reason to exist.
4. **GlossPop's define-once, link-forever loop** - a conversation/session-scoped glossary: first explanation of a term gets cached; every later use auto-links with no new LLM call. Cheap, fast, and it compounds across a long session.
5. **ponylang/llm-skills' invented-jargon flag, visually** - mark coined/unverifiable terms differently (icon or color) from real jargon, and ground the real/coined decision externally (web/codebase lookup), since the arXiv result says the model's own representations can't be trusted for that call. Even a coarse two-state badge ("defined in this conversation" vs "established term" vs "coined/uncertain") would be novel.

Honorable mention: Kindle Word Wise's difficulty slider as a density control (how aggressively to annotate) - useful once the basics work.
